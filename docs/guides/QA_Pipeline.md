# QA Pipeline (ob1-sandbox)

This document explains how the GitHub Actions workflow in `Sanchay-T/ob1-sandbox`
works, how it ties into Stage 1/Stage 2, and how to update it.

## Repos & Branches
- **CLI repo:** `https://github.com/Sanchay-T/open-code-blocks` (main branch)
- **Sandbox repo:** `https://github.com/Sanchay-T/ob1-sandbox` (main branch)
- Workflow file: `.github/workflows/qa.yml` inside `ob1-sandbox`

## Trigger
```
on:
  pull_request:
    branches:
      - main
```
Every PR to `main` runs the QA pipeline automatically. Stage 1 (`ob1 run ...`)
creates three PRs per task, so this pipeline runs three times per feature.

## Job Outline
```
jobs:
  qa:
    runs-on: ubuntu-latest
    steps:
      - checkout repo
      - setup Node.js
      - npm ci
      - install Playwright browsers
      - npm run build
      - npm run preview (background)
      - wait for http://127.0.0.1:4173
      - npx playwright test (records video, screenshots, traces)
      - kill preview server
      - upload artifacts (report + videos)
      - install `ob1` from main via PAT
      - run `ob1 qa --pr <number>` to post Claude QA review
```

### Secrets Required
- `CLAUDE_API_KEY` – stored as GitHub Actions secret in `ob1-sandbox`
- `GITHUB_TOKEN` – provided automatically by GitHub for each workflow

### Installing ob1 in CI
Workflow snippet:
```yaml
- name: Claude QA review
  if: always()
  env:
    CLAUDE_API_KEY: ${{ secrets.CLAUDE_API_KEY }}
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
  run: |
    python -m pip install --upgrade pip
    export OB1_REPO_URL="https://x-access-token:${GITHUB_TOKEN}@github.com/Sanchay-T/open-code-blocks.git"
    python -m pip install "git+$OB1_REPO_URL@main#egg=ob1"
    ob1 qa --pr ${{ github.event.pull_request.number }} \
      --target https://github.com/${{ github.repository }}.git \
      --build-log build.log \
      --test-log playwright.log \
      --artifacts "playwright-report, playwright-test-results"
```
This pulls the latest CLI from `open-code-blocks/main` using the PAT so CI is
always in sync with Stage 1 tooling.

### Artifacts Uploaded
- `playwright-report` – HTML report generated by Playwright
- `playwright-test-results` – raw videos, screenshots, traces

### QA Comment
`ob1 qa` uses the CLAUDE_API_KEY to:
1. Fetch PR metadata + files via GitHub API
2. Summarize build/test logs
3. Post a markdown review comment with status + video/report links

## How to Modify
- Edit `.github/workflows/qa.yml` in `ob1-sandbox`.
- For CLI changes, push to `open-code-blocks/main`; the workflow pulls that repo
  during every run.
- If you add new secrets (e.g., OPENAI_API_KEY), set them under
  `ob1-sandbox → Settings → Secrets and variables → Actions`.

## Troubleshooting
- **Missing `CLAUDE_API_KEY`:** workflow fails with “QA failed: CLAUDE_API_KEY must be set”. Add the secret to `ob1-sandbox`.
- **Playwright wait timeout:** ensure `npm run preview` listens on 4173; update port in `wait-on` if needed.
- **ob1 install issues:** verify `open-code-blocks` repo is public or PAT has access.

## Quick Checklist for New Devs
1. Fork/clone `open-code-blocks` and `ob1-sandbox`.
2. Ensure `CLAUDE_API_KEY` secret is set in `ob1-sandbox`.
3. Stage 1 command → PRs show up in `ob1-sandbox`.
4. Check PR → “QA Login Video” workflow shows video artifacts + Claude comment.
